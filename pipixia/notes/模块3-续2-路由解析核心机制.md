# 模块3-续2-路由解析核心机制（resolveAgentRoute）

## 核心概念

路由解析是Multi-Agent系统的"导航系统"，将入站消息映射到正确的Agent实例。

### 学前检测
- **resolveAgentRoute**：根据channel/accountId/peer解析目标Agent路由
- **AgentRouteBinding**：路由绑定配置 `{agentId, match: {channel, accountId, peer}}`
- **matchedBy**：路由匹配来源标识（debugging/logging用）

## 一、核心类型定义

### 1.1 ResolveAgentRouteInput

```typescript
export type ResolveAgentRouteInput = {
    cfg: OpenClawConfig;
    channel: string;
    accountId?: string | null;
    peer?: RoutePeer | null;        // { kind: "direct"|"group"|"channel", id: string }
    parentPeer?: RoutePeer | null;   // 线程父peer，用于绑定继承
    guildId?: string | null;         // Discord专有
    teamId?: string | null;          // Discord专有
    memberRoleIds?: string[];        // Discord角色匹配
};
```

### 1.2 ResolvedAgentRoute

```typescript
export type ResolvedAgentRoute = {
    agentId: string;                    // 目标Agent ID
    channel: string;                     // 渠道
    accountId: string;                   // 账号ID
    sessionKey: string;                  // 内部session key（持久化+并发控制）
    mainSessionKey: string;              // 主会话key（直接聊天折叠）
    lastRoutePolicy: "main" | "session"; // 谁接收inbound last-route更新
    matchedBy: MatchedBy;                // 匹配来源标识
};

type MatchedBy = 
    | "binding.peer"           // 直接peer绑定匹配
    | "binding.peer.parent"     // peer的parent匹配（如线程的父话题）
    | "binding.guild+roles"     // Discord: guild+角色匹配
    | "binding.guild"           // Discord: guild匹配
    | "binding.team"            // Discord: team匹配
    | "binding.account"         // 账号级别绑定匹配
    | "binding.channel"         // 渠道级别绑定匹配
    | "default";                // 默认路由（未精确匹配）
```

## 二、路由解析流程

### 2.1 分层匹配策略

```
resolveAgentRoute(input)
│
├─ L1: 精确peer绑定匹配
│   └─ bindings中是否有 {channel, accountId, peer.id} 的直接绑定？
│       └─ 是 → matchedBy="binding.peer" → 返回该agentId
│
├─ L2: parentPeer继承匹配
│   └─ 线程场景：peer没匹配，但parentPeer有绑定？
│       └─ 是 → matchedBy="binding.peer.parent" → 继承绑定
│
├─ L3: 账号级别匹配
│   └─ bindings中是否有 {channel, accountId} 的绑定？
│       └─ 是 → matchedBy="binding.account" → 返回该agentId
│
├─ L4: 渠道级别匹配
│   └─ bindings中是否有 {channel} 的绑定？
│       └─ 是 → matchedBy="binding.channel" → 返回该agentId
│
└─ L5: 默认兜底
    └─ matchedBy="default" → 返回 DEFAULT_AGENT_ID ("main")
```

### 2.2 关键设计：parentPeer继承

线程场景下，回复线程消息但线程参与者没有直接绑定时，可以继承parent（父话题/频道）的绑定：

```typescript
// 示例：线程消息路由
const route = resolveAgentRoute({
    cfg,
    channel: "discord",
    accountId: "acc1",
    peer: { kind: "channel", id: "thread-123" },
    parentPeer: { kind: "channel", id: "forum-channel" },
});
// 如果 thread-123 没有绑定，但 forum-channel 有 → 继承之
```

### 3.2 DM Scope控制

```typescript
type DmScope = "main" | "per-peer" | "per-channel-peer" | "per-account-channel-peer";
```

## 五、lastRoutePolicy（最后路由策略）

### 5.1 策略决定

```typescript
deriveLastRoutePolicy({
    sessionKey: "agent:main:...",
    mainSessionKey: "agent:main:...",  // 或 "main"
}): "main" | "session"

// 规则：
// - sessionKey === mainSessionKey → "main"（主会话接收更新）
// - 否则 → "session"（每个session独立接收更新）
```

### 5.2 应用场景

```
用户A在频道#general发消息 → 路由到Agent X → lastRoutePolicy=session
用户B在私信发消息给Bot → 路由到Agent main → lastRoutePolicy=main

当用户A下次在#general发消息：
- policy=session → 更新#general的会话
- policy=main → 更新main会话（可能不是A的）
```

## 七、核心API总结

| API | 职责 |
|-----|------|
| `resolveAgentRoute` | 核心路由解析（输入→ResolvedAgentRoute） |
| `buildAgentSessionKey` | 构建完整sessionKey |
| `buildAgentPeerSessionKey` | 构建peer隔离的sessionKey |
| `deriveLastRoutePolicy` | 决定lastRoute更新策略 |
| `resolveThreadSessionKeys` | 解析线程场景sessionKey |
| `listBindings` | 列出所有路由绑定 |
| `listBoundAccountIds` | 获取channel绑定的所有accountId |
| `buildChannelAccountBindings` | 构建channel→account→agentId映射 |
| `resolveDefaultAgentBoundAccountId` | 获取默认Agent绑定的accountId |

## 收获

1. **分层匹配**：peer → parentPeer → account → channel → default，优先级清晰
2. **matchedBy标识**：8种匹配来源，覆盖所有场景，方便debugging
3. **parentPeer继承**：线程场景的绑定继承设计，避免漏匹配
4. **DM Scope灵活度**：per-peer/per-channel-peer等粒度控制会话隔离
5. **lastRoutePolicy**：控制inbound last-route更新的目标会话
