## 一、模式检测（accounts.ts）

### 1.1 detectMode - 双模式架构

```typescript
export function detectMode(config: WecomConfig | undefined): ResolvedMode {
    if (!config || config.enabled === false) return "disabled";
    
    const accounts = config.accounts;
    if (accounts && typeof accounts === "object") {
        const enabledEntries = Object.values(accounts).filter(
            (entry) => entry && entry.enabled !== false,
        );
        if (enabledEntries.length > 0) return "matrix";
    }
    
    return "legacy";
}
```

**两种模式**：
- **matrix（矩阵模式）**：多账号并行，`config.accounts` 有启用条目
- **legacy（兼容模式）**：单账号，`config.bot` 或 `config.agent` 顶层配置

### 1.2 resolveWecomAccounts - 账号解析入口

```typescript
export function resolveWecomAccounts(cfg: OpenClawConfig): ResolvedWecomAccounts {
    const wecom = cfg.channels?.wecom as WecomConfig | undefined;
    
    if (!wecom || wecom.enabled === false) {
        return { mode: "disabled", defaultAccountId: DEFAULT_ACCOUNT_ID, accounts: {} };
    }
    
    const mode = detectMode(wecom);
    const accounts = mode === "matrix" 
        ? resolveMatrixAccounts(wecom)   // 解析多账号
        : resolveLegacyAccounts(wecom);  // 解析单账号
    
    return { mode, defaultAccountId, accounts, ... };
}
```

## 二、动态Agent路由（dynamic-agent.ts）

### 2.1 核心配置结构

```typescript
export interface DynamicAgentConfig {
    enabled: boolean;        // 是否启用动态Agent
    dmCreateAgent: boolean;  // 私聊是否创建独立Agent
    groupEnabled: boolean;   // 群聊是否启用动态路由
    adminUsers: string[];   // 管理员列表（绕过动态路由）
}
```

### 2.2 生成确定性Agent ID

```typescript
function sanitizeDynamicIdPart(value: string): string {
    return String(value)
        .trim()
        .toLowerCase()
        .replace(/[^a-z0-9_-]/g, "_");
}

export function generateAgentId(
    chatType: "dm" | "group", 
    peerId: string, 
    accountId?: string
): string {
    const sanitizedPeer = sanitizeDynamicIdPart(peerId) || "unknown";
    const sanitizedAccountId = sanitizeDynamicIdPart(accountId ?? "default") || "default";
    return `wecom-${sanitizedAccountId}-${chatType}-${sanitizedPeer}`;
}
```

**格式示例**：
- 私聊用户 u123：`wecom-default-dm-u123`
- 群组 g456：`wecom-default-group-g456`
- 多账号 a1 私聊：`wecom-a1-dm-u123`

### 2.3 shouldUseDynamicAgent - 决策逻辑

```typescript
export function shouldUseDynamicAgent(params: {
    chatType: "dm" | "group";
    senderId: string;
    config: OpenClawConfig;
}): boolean {
    const { chatType, senderId, config } = params;
    const dynamicConfig = getDynamicAgentConfig(config);
    
    if (!dynamicConfig.enabled) return false;
    
    // 管理员绕过动态路由
    const sender = String(senderId).trim().toLowerCase();
    const isAdmin = dynamicConfig.adminUsers.some(
        (admin) => admin.trim().toLowerCase() === sender
    );
    if (isAdmin) return false;
    
    if (chatType === "group") return dynamicConfig.groupEnabled;
    return dynamicConfig.dmCreateAgent;
}
```

**决策树**：
```
启用动态Agent?
├─ 否 → 使用默认Agent
└─ 是 → 发送者是管理员?
         ├─ 是 → 使用默认Agent（绕过）
         └─ 否 → 私聊? → dmCreateAgent
                  └─ 群聊? → groupEnabled
```

## 三、默认路由拒绝策略（routing.ts）

### 3.1 failClosedOnDefaultRoute

```typescript
export function resolveWecomFailClosedOnDefaultRoute(
    cfg: OpenClawConfig
): boolean {
    const wecom = cfg.channels?.wecom as WecomConfig | undefined;
    const explicit = wecom?.routing?.failClosedOnDefaultRoute;
    
    if (typeof explicit === "boolean") return explicit;
    return detectMode(wecom) === "matrix";  // matrix模式默认开启
}
```

**安全策略**：
- **matrix模式**：默认开启 fail-closed，未知路由必须拒绝
- **legacy模式**：默认关闭，维持历史兼容行为

### 3.2 shouldRejectWecomDefaultRoute

```typescript
export function shouldRejectWecomDefaultRoute(params: {
    cfg: OpenClawConfig;
    matchedBy: string;       // 路由匹配来源：default/binding.account/...
    useDynamicAgent: boolean;
}): boolean {
    // 非默认路由直接放行
    if (params.matchedBy !== "default") return false;
    // 动态Agent路由已处理，不拦截
    if (params.useDynamicAgent) return false;
    // 检查failClosed策略
    return resolveWecomFailClosedOnDefaultRoute(params.cfg);
}
```

**拦截条件**（同时满足）：
1. `matchedBy === "default"`（未精确匹配）
2. 未启用动态Agent
3. 配置为matrix模式且未显式关闭failClosed

### 4.1 隔离机制

每个用户/群组拥有独立Agent的核心原理：

```typescript

const agentId = generateAgentId(chatType, peerId, accountId);
const sessionKey = `wecom:${agentId}:${fromUser}`;

// 路由时根据sessionKey选择对应Agent
await core.channel.reply.dispatchReplyWithBufferedBlockDispatcher({
    ctx: { SessionKey: sessionKey, ... },
    cfg: config,
    // ...
});
```

## 五、设计思想

### 5.1 分层决策

| 层次 | 决策点 | 依据 |
|------|--------|------|
| L1 | 模式选择 | detectMode → matrix/legacy |
| L2 | 动态路由 | shouldUseDynamicAgent |
| L3 | 账号解析 | resolveWecomAccount |
| L4 | 默认拦截 | shouldRejectWecomDefaultRoute |

### 5.2 安全闭环

```
消息进入 
    → 检测模式(matrix/legacy)
        → 动态Agent路由?
            → 是 → 生成确定性AgentID
            → 否 → 使用默认Agent
        → 是默认路由?
            → 是 + matrix → 拒绝(failClosed)
            → 否 → 放行
```

### 5.3 幂等保障

- 内存Set：防止重复处理
- 串行队列：避免并发写入冲突
- 配置持久化：重启后可恢复

## 收获

1. **双模式架构**：matrix（多账号隔离）vs legacy（兼容）的平滑切换
2. **确定性路由**：基于 `accountId + chatType + peerId` 生成唯一Agent ID
3. **安全fail-closed**：matrix模式默认拒绝未知路由，防止串会话
4. **幂等设计**：内存Set + Promise队列避免重复写入
5. **会话隔离**：每个用户/群组拥有独立sessionKey，实现真正多租户
